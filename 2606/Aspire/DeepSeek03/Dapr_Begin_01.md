# 3 Введение в Dapr (Distributed Application Runtime)

---

## Что такое Dapr

**Dapr (Distributed Application Runtime)** — это не зависящая от платформы событийно-ориентированная среда выполнения с открытым исходным кодом. Она спроектирована для упрощения разработки распределенных микросервисных систем.

Основная идея Dapr заключается в том, чтобы забрать на себя решение сложных инфраструктурных задач, позволяя разработчику сосредоточиться исключительно на написании бизнес-логики.

## Архитектурный паттерн Sidecar («Коляска»)

Dapr функционирует на базе паттерна **Sidecar**. Это означает, что рядом с каждым инстансом вашего микросервиса запускается отдельный независимый процесс (Dapr Sidecar).

### Механизм взаимодействия

* Приложение **никогда не общается** с базами данных, брокерами сообщений или другими сервисами напрямую.
* Приложение делает локальный вызов к своему Sidecar через быстрый локальный протокол **HTTP** или **gRPC**.
* Dapr Sidecar принимает запрос, выполняет необходимую системную операцию и возвращает результат приложению.

## Ключевые строительные блоки (Building Blocks) Dapr

Dapr предоставляет разработчику готовый набор универсальных API («строительных блоков»), абстрагирующих нижележащую инфраструктуру:

### 1. Service-to-Service Invocation (Вызов сервисов)

Гарантирует надежный и защищенный обмен данными между микросервисами. Dapr автоматически берет на себя обнаружение адресов (Service Discovery), шифрование трафика (mTLS) и политики повторных попыток при сбоях (Retries/Circuit Breaker).

### 2. State Management (Управление состоянием)

Предоставляет единый API для сохранения и чтения данных в формате «ключ-значение». Вы можете переключать реальное хранилище данных (например, заменить Redis на PostgreSQL или AWS DynamoDB) одной строкой в конфигурации, **не меняя ни одной строчки кода** в самом приложении.

### 3. Publish and Subscribe (Pub/Sub)

Обеспечивает асинхронный обмен сообщениями между независимыми облаками или сервисами. Dapr абстрагирует работу с брокерами (RabbitMQ, Kafka, Azure Service Bus, NATS), стандартизируя формат событий по спецификации CloudEvents.

### 4. Bindings (Привязки к ресурсам)

Позволяет приложению реагировать на внешние события (входящие триггеры) или отправлять данные во внешние системы (исходящие привязки), например, отправить SMS через Twilio или вызвать AWS Lambda без подключения тяжелых SDK.

### 5. Actors (Виртуальные акторы)

Предоставляет изолированную однопоточную модель вычислений с сохранением состояния. Идеально подходит для сущностей, требующих жесткой изоляции параллельного доступа (например, торговый счет пользователя, игровой персонаж или инвентарный стек).

## Главные преимущества Dapr для архитектуры

* **Полная независимость от инфраструктуры (Vendor Lock-in):** Код пишется под абстрактный API Dapr. Локально данные могут храниться в Redis, а на Production-сервере — в защищенном облачном кластере. Смена провайдера происходит через конфигурационный YAML-манифест.
* **Сквозная безопасность на периметре:** Трафик между всеми Dapr Sidecar автоматически шифруется по умолчанию (встроенный mTLS), исключая риски перехвата данных внутри сети.
* **Встроенная наблюдаемость (Observability):** Все межсервисные вызовы и операции с шиной данных автоматически логируются и трассируются по стандарту OpenTelemetry без ручного подключения middleware.
