
Шаг 1. Подготовка репозитория в GitVerse

Сначала создайте центральное хранилище, куда будут стекаться все документы.
• Регистрация и создание проекта. Создайте пустой приватный репозиторий в GitVerse (например, product-docs).
• Клонирование на компьютер. Установите Git и скачайте пустой репозиторий в удобную папку на вашем ПК. Если командная строка непривычна, используйте бесплатный визуальный клиент (например, GitHub Desktop или Fork — они работают с любым Git, включая GitVerse).

Шаг 2. Базовая настройка Obsidian

Превратите скачанную папку в хранилище Obsidian (Vault) и сразу задайте правильные правила, чтобы потом не переделывать сотни файлов.
• Открытие папки. В Obsidian выберите «Открыть папку как хранилище» и укажите папку вашего репозитория. Папка .obsidian с настройками тоже попадет в Git, что удобно для сохранения единых правил.
• Формат ссылок. Зайдите в Настройки -> Файлы и ссылки. Отключите опцию «Использовать вики-ссылки» (Use Wikilinks). Установите «Формат новых ссылок» в значение Относительный путь к файлу (Relative path to file).
• Папка для картинок. В том же меню настроек выберите «Местоположение для новых вложений» -> В указанной папке и впишите assets. Теперь все вставленные скриншоты будут аккуратно складываться в одно место.

Шаг 3. Простая структура папок

Не усложняйте иерархию на старте. Достаточно трех базовых разделов:
• 01-products/ — описания самих программных продуктов, их функций и архитектуры.
• 02-guides/ — инструкции для пользователей и администраторов (как установить, как настроить).
• 03-processes/ — внутренние регламенты, частые вопросы (FAQ) и база знаний команды.
• README.md — главный файл в корне, который служит оглавлением. GitVerse автоматически покажет его на главной странице репозитория.

Шаг 4. Ежедневный рабочий процесс

На первом этапе вашим «веб-порталом» для чтения будет сам интерфейс GitVerse. Он умеет красиво отрисовывать Markdown-таблицы, код, картинки и переходы по ссылкам прямо в браузере.
• Написание. Вы создаете и редактируете файлы в Obsidian.
• Сохранение. В конце дня или после завершения задачи делаете commit и push в GitVerse.
• Чтение. Любой сотрудник, у которого есть доступ к репозиторию, открывает ссылку в браузере и читает актуальную версию документации.

Когда переходить к следующему этапу

Задумываться о подключении генераторов сайтов (MkDocs) или автосборке PDF стоит только тогда, когда появятся первые реальные неудобства:
• Документацию нужно показать внешним клиентам, которым нельзя давать доступ в ваш GitVerse.
• Файлов станет больше 50–100 штук, и понадобится быстрый полнотекстовый поиск по всем разделам сразу.
• Потребуется красивое брендирование страниц под стиль вашей компании.
Можем сразу сделать заготовку для старта:
• Написать шаблон главного файла README.md с удобной навигацией
• Подготовить шаблон описания программного продукта (структуру заголовков для .md файла)
